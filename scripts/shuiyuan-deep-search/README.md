# 水源深度搜索助手

Shuiyuan Deep Search 会把问题拆成多组站内检索，精读相关水源主题，并生成可追溯到原帖的结构化报告。报告生成后，可以在同一对话中继续追问；既有证据不足时，脚本会自动补充搜索和阅读新主题。

## 功能

- 把自然语言问题拆成 3–6 个互补的 Discourse 检索式。
- 首轮包含独立核心词检索，并兼顾外文缩写与模型给出的中文常用名，避免所有检索式都过度限定。
- 名词搜索默认整理相关资讯与社区经验，研究角度围绕用户所需内容；只有明确询问名称、定义或身份时才以辨析为重点。
- 同时探索原称谓、可能的正式名称、简称和类别/用途；不确定名称分开搜索，并生成放宽关键词的方向。
- 每个搜索阶段通过相关性筛选的未读主题不足 3 个时，最多追加 2 轮联想检索，每轮最多 3 个新检索式；结合命中数、标题和摘要调整检索方向，避免重复检索。零结果时也会先尝试扩展。
- 最多并行执行 4 个站内搜索、3 个主题读取，自动去重并排序。
- 每批搜索结果由 LLM 根据标题和摘要筛选、按相关性排序后再精读，减少仅共享品牌或通用词的无关帖子。
- 兼容模型返回数字或数字字符串的主题 ID。若有搜索结果但摘要筛选全部排除，最多精读 2 个未读主题核实，最终按正文判断是否可作证据，不把筛选为空误报为站内零结果。
- 相关性筛选与下一轮补搜规划合并为一次 LLM 请求；筛选只发送每帖最多 240 字符摘要和最近 18 条检索记录。
- 分页精读候选主题；默认首轮最多读取 8 个主题、每个主题 30 条帖子。
- 首轮阅读后检查证据缺口；资料不足时最多追加 2 个检索式并补读主题。
- 生成摘要、分项结论、证据限制和后续问题，每条引用均链接原主题。
- 每次追问先判断是否需要新证据；必要时生成最多 3 个检索式，并补读最多 3 个未见主题。
- 支持任意 OpenAI-compatible Chat Completions API 地址，默认使用 DeepSeek。
- 显示逐阶段进度，支持中止尚未完成的水源和 LLM 请求。
- 显示搜索候选数；真正没有候选主题时，列出实际检索式与命中数，便于在原生搜索中核对。模型返回无效 ID 或字段时会单独报错。
- 入口位于水源顶部原生搜索按钮左侧；持续同步原生按钮和图标尺寸，适应窗口尺寸变化和导航栏重建。研究面板运行在隔离的 Shadow DOM 中。
- 自动跳过能够识别出的 Discourse 私信主题。

脚本仅运行于：

```text
https://shuiyuan.sjtu.edu.cn/*
```

## 安装与配置

1. 安装 Tampermonkey 或 Violentmonkey 等用户脚本管理器。
2. 从 GreasyFork 安装本脚本。
3. 登录水源，点击顶部原生搜索按钮左侧的“放大镜 + 星芒”图标。
4. 首次使用会直接打开设置。填写 API 地址、模型和 API Key，然后保存并返回。
5. 如需再次配置，点击面板右上角的滑杆图标。

默认 API 地址为 `https://api.deepseek.com/chat/completions`，默认模型为 `deepseek-v4-flash`。也可以填写其他 OpenAI-compatible `/chat/completions` 地址及其模型名称，例如 OpenAI 的 `https://api.openai.com/v1/chat/completions`。

自定义远程地址必须使用 HTTPS；`localhost`、`127.0.0.1` 和 `[::1]` 可以使用 HTTP 且 API Key 可留空。脚本预先声明 DeepSeek、OpenAI 和常用本机地址，并同时声明 `@connect *`；首次连接其他域名时，用户脚本管理器可能要求你确认该域名或全部域名的访问权限。

## 使用

输入问题，点击“开始研究”或按 `Ctrl/⌘ + Enter`。脚本依次规划、搜索、精读、检查证据缺口并生成报告。点击来源可在新标签页查看原主题。

名称不确定时可以保留记忆中的叫法，并补充品牌、用途或类别。有明显合理的对应对象时，报告会简短说明可能所指，然后整理相关资讯、经验和使用条件；仅在多个合理对象会实质改变答案时澄清。名称联想用于找帖，不作为默认报告章节。具体结论仍须有帖子证据，价格和规则等信息应保留适用时间与条件。

首轮、证据补搜和追问补搜都支持相关结果不足时的联想检索；补搜优先填补用户需要的信息，而非反复验证名称拼写。精读主题上限不变，但相关性筛选和联想可能增加搜索及 LLM 请求次数。

报告完成后，在底部输入追问，或点击建议问题。脚本会先检查现有报告、对话和来源是否足够；如有必要，会搜索并补读新主题后再回答。每次追问最多补读 3 个主题，整个会话最多保留 `max(12, 首轮主题上限 × 3)` 个主题。刷新页面会清空当前报告和对话。

为控制等待时间，追问请求使用截短的报告和最近 4 轮对话（每轮历史回答最多 600 字符），规划阶段每帖摘录最多 600 字符；最终回答仍可使用已精读的来源正文。完整报告和对话保留在页面内存中，但早期对话细节可能不在本轮模型上下文中。报告默认简洁输出，可在问题中明确要求详述。

## 隐私与网络请求

脚本在用户脚本管理器的本地存储中保存 API 地址、API Key、模型名、首轮主题上限和每主题帖子上限。报告和对话仅保存在当前页面内存中。

脚本会发出两类请求：

- 向 `https://shuiyuan.sjtu.edu.cn/search.json` 和主题 JSON 地址发出同源请求，使用浏览器现有登录会话读取当前账户有权查看的内容。
- 向用户配置的 LLM API 地址发送问题、检索计划与命中数、候选主题标题和摘要、选中主题的作者用户名、日期与正文片段、报告和追问；如填写 API Key，会在 `Authorization: Bearer …` 请求头中发送。一次研究只会请求当前配置的地址。

为访问用户自行填写的域名，脚本声明了 `@connect *`。代码不会枚举或请求其他域名；实际 LLM 请求目标始终来自设置中显示并保存的 API 地址。

水源 Cookie、站点密码和其他登录凭据不会发送给 LLM 服务。帖子正文可能含个人信息；请勿用它处理敏感或不宜上传的内容。脚本会主动排除标记为私信的主题，但无法判断普通主题正文是否敏感。

## 兼容性与限制

- 需要登录水源、可用的 OpenAI-compatible Chat Completions 服务，以及允许相应域名网络请求的用户脚本管理器。
- 自定义服务必须接受 `model`、`messages` 和 `response_format: {"type":"json_object"}`，并在 `choices[0].message.content` 返回 JSON 文本。
- 依赖 Discourse 的搜索与主题 JSON 结构；站点升级后可能需要更新。
- 搜索结果受索引、当前账号权限和排序影响，不代表社区全部内容。
- 为控制上下文和费用，主题数、帖子数和上传字符数均有限；很长主题的后部内容可能未进入报告。
- 相关性筛选、研究目标、新检索式及证据缺口由模型判断；可能误判、漏掉有用主题，或给出不理想的检索式。无法保证纠正每个错误名称。重要决定请沿引用阅读原帖核查。
- 需要在已登录的水源页面用目标用户脚本管理器完成手工冒烟测试，尤其应检查顶部入口样式、输入时的快捷键隔离、自定义域名授权和追问补搜流程。
